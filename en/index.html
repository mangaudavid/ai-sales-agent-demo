What is actually happening

No magic, no marketing. Four mechanisms — the same ones I build in production for clients.

1 · retrieval

Hybrid: lexical + constraints

BM25 over product text, combined with matching on structured attributes (volume, voltage, port size, budget). The scores in the side panel are computed live for your question, not pre-baked.

2 · reasoning

Five compatibility rules

Sizing by pool volume, physical port matching, electrical compatibility, the pump→filter→controller chain, and discontinued products with their replacement. Semantic search alone solves none of these.

3 · grounding

Every number has a source

Prices, stock levels and specs in the answer are cited with the SKU and the exact field they came from. If a fact isn't in the catalog, it can't appear in the answer — by construction, not by instruction.

4 · refusal

Refusal is an outcome, not an error

Non-existent product, discount request, missing information, out-of-scope question — each has an explicit refusal path, visually marked. This is the part vendors don't show you.

What this demo does and doesn't do

A demo that hides its limits is a demo that lies. Below is the real boundary.

Does

  • Real retrieval, computed live for every question
  • Reasoning over structured attributes, not just text similarity
  • Claim-level citations, verifiable against the catalog
  • Explicit refusal in four distinct situations
  • Runs offline, instantly, at zero cost, with no account

Does not

  • There is no LLM behind this page — composition is deterministically grounded in the retrieved fields. The systems I ship to clients do use an LLM, with the same grounding guarantees
  • It doesn't understand every phrasing. A production system has query rewriting and a far richer language layer
  • The catalog is fictional and small (75 products). In production I work on catalogs of thousands of SKUs, synced live over an API
  • It has no memory between questions

The production system behind this demo

This page is a sanitised, offline version. The real one runs on a client's live catalog.

4,400 SKUs, live

A conversational sales agent over a technical heating and HVAC catalog, synced incrementally over the client's API. Hybrid retrieval on Qdrant: multilingual-e5-large dense plus BM25 sparse, RRF-fused, reranked with jina-reranker-v2 over a 60-candidate pool. 97.7% hit-rate@5 on a golden set. Self-hosted on the client's own EU infrastructure — FastAPI, Qdrant, Redis, n8n, Caddy — at roughly €9/month, ~$0.001 per conversation.

The hard part wasn't the model

Their catalog API returned no category field, so semantic search kept confusing a wood stove with a gas boiler. I derived category and specs deterministically from product names at ingest — 23 rules over 4,373 SKUs. For superlatives and budgets I bypass ranking entirely with an exact catalog scan, because "cheapest under 1,500" is definitional, not statistical. And the model never writes a product fact: it picks an index from a numbered list of real rows, and code renders the card.

Shipped through a compliance gate

The client imposed 13 blocker acceptance criteria before go-live: EU AI Act Art. 50 transparency, GDPR Art. 28 processor obligations, an anonymous-by-design architecture where no personal data reaches the model, logs or analytics, a retention and deletion policy, a tested kill switch and rollback. I owned all of it, alone, against a spec that moved weekly.

The evaluation harness

The artefact I'd rather be judged on than a CV. Open source, MIT, standard library only.

224 adversarial cases

Ten categories: prompt injection, jailbreak, PII leakage, off-topic, multilingual, safety, grounding, over-refusal. It runs through the real pipeline with an LLM judge — not against mocks. Pluggable agent adapters, a configurable judge, and a fail-closed redaction checker.

It tests both directions

Most eval suites only punish hallucination. That trains you to ship something uselessly timid, which is its own failure. Half of these cases check that the agent answers when it should — because a refusal that leads nowhere is a lost sale, and the client is right to complain about it.

77% → 87% → 90%

Three measured iterations on the production build. Guardrail categories sit at 95-100%. Two things it caught that would otherwise have shipped: a wood stove sold as a gas boiler, and — worse — the agent answering "my boiler broke" by trying to sell a new one instead of routing to authorised service.
